# 개인정보와 공개 파일 경계

실제 계정 경로가 담긴 설정, 수집 DB/WAL/백업, 실행 로그, 스크린샷, 메모리 조사 결과, 키·토큰·암호·계정 식별자는 개인 PC에만 보관합니다. 가능하면 개인 설정과 수집 DB는 공개 저장소 디렉터리 밖에 두세요. `.gitignore`는 이미 Git에 기록된 파일을 제거하지 않습니다.

공개 예시·fixture에는 실제 이름, 개인 절대 경로, 프로필 해시, author/chat ID, 범주 이름, 대화 본문을 사용하지 않습니다. `YOUR_NAME`, `YOUR_PROFILE`과 생성한 가상 데이터를 사용합니다.

Git 커밋의 작성자 이름과 이메일도 기록에 포함됩니다. 개인 이메일을 공개하지 않으려면 GitHub의 noreply 주소를 사용하고, 저장소 공개 전에 기존 커밋 기록도 확인하세요. 파일 내용 검사만으로 작성자 정보까지 제거되지는 않습니다.

수집기는 원본을 읽고 선택된 방의 대화를 로컬 DB에 기록합니다. 키는 파일·로그에 저장하지 않습니다. STDIO MCP 결과가 클라우드 AI 호스트에 반환되면 조회한 대화가 해당 서비스로 전달될 수 있습니다.

범주에서 제외된 데이터는 활성 DB에서 제거하고 SQLite `secure_delete`를 사용합니다. 이전 백업, 호스트가 받은 결과, 디스크 사본, Python 메모리를 완전히 회수/영점화하는 기능은 없습니다.

실행 경로·생성 시각을 확인해 프로세스 종료·PID 교체 시 캐시를 폐기합니다. 실패·만료된 방은 최신 대화로 반환하지 않습니다. **프로세스가 살아 있는 상태의 앱 내부 로그아웃 감지와 기존 DB 키 유효성은 실제 검증을 완료하지 않았습니다.** 복사된 과거 DB가 로그아웃만으로 해독 불가능해진다고 보장하지 않습니다.

커밋 전 `git status --short --untracked-files=all`, `git diff --cached`, `git ls-files`로 소스·문서·가상 테스트만 기록되었는지 확인합니다. 개인 설정이나 대화 자료를 공개 이슈에 첨부하지 마세요.
